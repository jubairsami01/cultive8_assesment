How does it work?
  1. The log is split into parts that fit the model's 2,048-token window. Line numbers are kept and entries are never cut.
  2. The local model reads one part at a time. Facts from earlier parts (for example, failed logins by an IP) are carried forward so events far apart in the file get linked.
  3. Findings are saved after every part, then merged into one report with evidence line numbers.

Text inside the log is treated as data only. Instructions written in a log are never followed.
